# Optimist UI: how it works now

The Optimist UI is the only user interface of the firmware (SLOOP's UI was removed on 2026-10-19). This page is the reference for how it is built and why: the grammar, the screens, the rules that cut across them, and where each lives in the code. Old design history, build logs and size tables are in git (`git log -- docs/UI-OPTIMIST-DESIGN.md`).

Two other pages carry the user's view and are not repeated here: [guide/shortcuts.md](guide/shortcuts.md) lists every gesture, [guide/interface.md](guide/interface.md) explains the controls and pages. Where this page and the code differ, the code wins: report it.

The look and the first screens come from Felucca 1.0 (Leo Kuroshita, GPL-3.0-only); NAME is ported from its `ui_name.c`, the step conditions and the sequence tools from Felucca 1.5.6 (credits: LICENSING.md).

## 1. Basics

### 1.1 The hardware and the screen

- 14 buttons: FX SCL ENV LFO EDIT GLO HOME SAVE ARP SEQ PLAY REC OCT- OCT+. 7 encoders: SELECT, ALGORITHM, PRESETS, KNOB 1..4. No encoder pushes.
- 27 keys: 16 white (F3..G5), 11 black (F#3..D#5 and F#5). On the drum track the white keys are always steps and the black keys are the lanes.
- 240 x 240 screen. A canvas holds at most 124 rows, so screens draw in bands of at most 240 x 124, each redrawn only when its signature changes (`op_draw.c`).
- Layout (y): header 0..24; the cards 28..120 as a 2 x 2 block (the mixer: four small cards 28..72); the panel under them; the help band 219..236 when the build has the help line (section 12); the load lines' rows 237..239 (section 3.6).
- Button LEDs, key LEDs and PLAY's second lamp: section 11.

### 1.2 The code

All of it is `firmware/src/ui/optimist/` (about 19,500 lines, one translation unit through `optimist.c`). It calls the core (`core/`, `seq/`, `drums/`, `fx/`, `storage/`) and owns no audio state.

| File | Holds |

| `op_walk.c`, `op_combos.c`, `op_edits.c`, `op_keys.c` | ALGORITHM's walk and a lane's sound; SAVE / SHIFT + a button; the "discard edits?" signatures; the keys' lights |
| `op_cells.c`, `op_names.c`, `op_effval.c` | cells (label, value, unit, kind) made from the shared pages; the names table; effective values |
| `op_screens.c`, `op_mixer.c`, `op_mixdraw.c` | SOUND and the master FX; the mixer's rows and sets; its drawing |
| `op_step.c`, `op_stepdraw.c`, `op_tools.c` | STEP; its grid and roll; TOOLS, GEN, GEN OUT |
| `op_global.c`, `op_gldraw.c`, `op_bt.c`, `op_wifi.c`, `op_project.c`, `op_prjflow.c`, `op_sdcard.c` | GLOBAL and SYSTEM lists and their drawing, the SYSTEM table; the Bluetooth pages; the WI-FI page and its password entry (included late, felucca.c after the console: it drives the Wi-Fi manager); PROJECT; the card's lists (SD card mode) |

A screen is five functions (rows, a row's name, a cell, a turn, a YES). A cell is a label, a value, a unit and a kind (value, read-out, action, a row to enter), mostly straight from a descriptor of the shared tables (`core/params.c` PAGES) and `param_format`, so a value lives in one place and the web editor shares its names.

## 2. The grammar

Every screen is a list of rows. A row has up to four cells; the cells of the cursor row are the four cards and KNOB 1..4 edit them. Nothing has to be held to edit.

### 2.1 The knobs

| Control | Does |
|---|---|
| SELECT | the cursor: which row (or page). Stops at the ends |
| ALGORITHM | the track, on every screen that has one: RET A B C, MASTER, T1 T2 T3, DR, the 10 drum lanes, ACCENT (2026-10-30, the master group first since 2026-10-31; the mixer: USB IN after the lanes). Stops at both ends. Section 2.7 lists where it does nothing |
| PRESETS | the selected track's sound, one a detent: a synth preset, DR the kit, a lane on its own source that lane's sound. On STEP it scrolls the 16-step window; on GLOBAL, SYSTEM and MASTER it does nothing; under a question, the REC ring and NAME it does nothing |
| KNOB 1..4 | the cursor row's four cells; a turn makes its cell hot |
| SHIFT + a knob | the value back to its default (the mixer's volume cards: the row's mute) |
| SHIFT (OCT-, left) + PRESETS | a synth track: the next / previous engine (instrument), its first sound, in the whole list's engine order (the ENGINE card's), whatever the filter, stopping at the first and last; DR and a lane on KIT: the kits; a lane on its own source: the next kind. Not on STEP |
| SHIFT2 (OCT+, right) + PRESETS | a synth track: the preset list's filter, one a detent, round: ALL, FACTORY, USER, FAVORITES (builder item `FAVORITES`), INIT. The sound playing stays. The popup list shows the filter in its header (section 4.9). STEP: the window follows the playhead again. The drum track: nothing |
| SHIFT2 (OCT+) + SELECT | the keys' velocity, 1..127 a detent (100 the default, what the keys always gave), played and recorded into the step; a toast *VELOCITY: n*. Not kept over a power cycle. Not on STEP (its cards for the long time), SONG, GLOBAL, SYSTEM |

Keys' velocity, the reporter of issue #134: *"It would be also great to set the velocity of the keyboard while playing. On Felucca, one can remap the Select knob to alter Velocity in real time."* Here it is SHIFT2 + SELECT (no setting to remap, SELECT alone keeps moving the cursor); `seq.c key_vel`, `op_input.c kvel_turn`. A note's own velocity in the piano roll is the step's LEVEL card (section 4.2).

The shifts on PRESETS, the user, 2026-10-31: *"Left shift plus preset should go to the next/prev engine. Right shift should cycle thru (filter) types of preset. Factory, user, favorites/init etc. With some visual feedback so that the user understands (keep the filter at the top of the list, and make it taller). Also when scrolling the top of the list flash"*. Left shift is OCT- (SHIFT), right shift OCT+ (SHIFT2), as the buttons sit and as the user named SHIFT2 + SELECT "right shift + select" on 2026-10-23. Before, SHIFT2 + PRESETS stepped the engine and SHIFT + PRESETS did nothing; SHIFT2 + SELECT (favorites only / all) is folded into the filter and gone. This ruling goes before section 2.3's reading of the shifts for PRESETS.

The filters (`model.c pl_filt`, `pl_source`; `op_screens.c PLF_ORDER`): **ALL** every sound (the whole list); **FACTORY** the factory sounds and the FM6 voice packs; **USER** the user presets and the collections' slots the player fills (the DX7 bank received, the CZ tones); **FAVORITES** the marked sounds; **INIT** each engine's INIT, one an engine (an INIT edited since reads as outside the list). A filter lists its sounds of every engine, EDIT's PRESET card too (as FAVORITES always did). A sound playing outside the filter: the list from its top, nothing lit, *0/N*; PRESETS then goes to the list's first (right) or last (left). An empty filter: the popup all the same, *NONE*. Not kept over a power cycle (ALL). The web editor's FAVS op 3 sets FAVORITES or ALL; its op 0 reads 1 only for FAVORITES.

PATTERN's LEN moves through 1 2 4 8 16 32 64 and an LFO's PHS by 45 degrees; LFO held + the knob (or PRESETS) moves either by one.

### 2.2 Taps, holds, YES and NO

- SAVE tapped is YES: enter a row, toggle an on / off value, do an action, confirm a question. HOME tapped is NO: cancel, go to the mixer, nothing else changed (the track, lane or return selected and the page kept; HOME again: SCOPE, section 4.1).
- SAVE, HOME and the page buttons act when let go, and only if nothing else was pressed, turned or played meanwhile. That is how a tap, a layer and a chord are told apart.
- A hold is 350 ms by default, one threshold for every tap-or-hold decision (a layer's map, PLAY for TEMPO, a step key, NAME). SYSTEM > CALIBRATE > HOLD sets 250 / 350 / 500 ms (`core/hold.h`, settings word bits 21..22). A page button let go within hold + 150 ms still counts as a tap.
- A page button tapped goes to its family's rows; tapped again, to the next row, past the last the first (section 2.4).

### 2.3 The two shifts, and SAVE

SHIFT is OCT- held, SHIFT2 is OCT+ held. They read one language, as the buttons sit (OCT- down, OCT+ up):

- **SHIFT: off, less, remove.** Mute, clear, default, a ghost hit, the panic, INIT, a return muted.
- **SHIFT2: pick, on, more.** Select, a hard hit, a set step on STEP: its level up and mute cycled (2026-11-01), launch now, the preset list's filter, a layer locked open, STEP's window following again. (The next instrument or kind is SHIFT + PRESETS since 2026-10-31, the user's left shift: section 2.1.)
- OCT- and OCT+ change the octave (-3..+3) when let go, and only if no other control was used while held. Both tapped together (let go within 400 ms): the track <-> MASTER toggle: the mixer with MASTER selected (2026-10-30), again back to the page and track left; on a synth track's STEP, FOLD instead (section 4.2).
- HOME is only HOME / NO. SAVE is never a shift: it saves.

Keys under the shifts: black key n is drum lane n, the last upper key the ACCENT lane, white keys 1..4 are T1 T2 T3 DR. PROJECT and SONG, whose keys have their own job, take no shifted key (section 2.7). `shift_keys` in `op_input.c`.

### 2.4 Paging

1. A page button tapped again goes to its next page and, past the last, to the first (ENV LFO FX SCL ARP EDIT on SOUND; FX on the master FX; SEQ on STEP; a page button with a step held; OCT-/OCT+ in the FM6 layer). GLO is the exception: it switches GLOBAL and SYSTEM.
2. SELECT moves through the same pages forwards and back and stops at the ends: a knob that wraps loses the user's place.

SELECT's other jobs: a held step: the step's card pages; the mixer: the row's knob sets; GLOBAL / SYSTEM: a page of four lines; PLAY held: TEMPO's rows. A layer held: nothing. SCOPE has one page. NAME: nothing.

Every screen remembers its page (RAM only, cleared at power-on): SOUND per track and per family, STEP's row, the held step's card page per track, the lists' cursor, the mixer's set. A row a track no longer has falls back to the nearest. Not remembered: layers, NAME, a modal. `snd_mem`, `hp_mem`, `ui.row[]`.

### 2.5 Questions, toasts and what asks

- **One confirm.** A destructive action arms and a modal box covers the panel: the verb large, the target large in its colour (a track in its engine's colour), "HOME no" left and "SAVE yes" right at the box's foot. The frame is red when the action destroys or replaces work, amber otherwise. YES does it; NO, another row or 3 s let it go. Cards, header and help line stay.
- **Toasts.** What a confirmed action says (*T2 CLEARED*, *SAVED*, a preset's name and engine) is a small box in the middle of the panel for about 1.5 s, framed in the colour of its words. Passive status (MISSING, RECORDING, STOP BEFORE SAVE) is a header message for about 2.5 s.
- An action card shows its verb, never "YES"; its small label is its object. CLEAR, ERASE, NEW, INIT, DELETE are drawn in the alarm colour. A knob turn only picks an action card, it never runs it. Help lines say "(asks)".
- **Red** means destroys or replaces work and nothing else (`prj_danger`, `go_danger`): SAVE and DELETE over a used slot, LOAD over edited work, NEW always, INIT, FORGET. SONG REC is never red (green recording, amber armed); only "Record over song?" is.
- **What asks** (`op_edits.c`): everything that replaces an edited sound ("Discard T2 edits?": PRESETS, SHIFT + PRESETS, the SOUND row's PRESET and ENGINE, a lane's own sound, the kit), INIT, a user preset's LOAD; a scene or project LOAD only when the work differs from what was last loaded, stored or made NEW; SONG REC over a stored song; a scene or pattern store over a used slot, and every clear; SONG's DELETE part; a lane's RESET / SAVE / ERASE; FM6 STORE / SEND / INIT; CALIBRATE PANEL; BLE FORGET.
- A sound is *edited* when the values a preset sets (`model.c param_kept`) and, on the drum track, the lanes' sounds and sends differ from when it was loaded or saved. Recorded motion that writes values while playing may make a sound read as edited (it asks; never the other way).
- Not asked, because undo covers them: STEP's TOOLS, single-step edits.

### 2.6 Undo and redo

SAVE then HOME is undo, HOME then SAVE is redo; both act when one of the two is let go, with nothing else used. Several levels on every track; each step key pressed, a lock written, a motion pass and a clear opens one (`seq/undo.c` keeps steps, the automation list and LEN / DIV). On STEP with a note picked, SAVE held alone and HOME held alone are mute and delete (section 4.2), which is why the chords act on release.

### 2.7 Pages with no track

The keys play the selected track on every page without a track of its own (the user, 2026-10-30: "every page without a track", "exception the patterns/save page that use the keyboard of course"; it supersedes 2026-10-13's "global pages dont play tracks"): GLOBAL, SYSTEM (INFO's meters while playing; the BLE devices list too), the master FX, SCOPE, and the mixer's MASTER, return (RET A B C, 2026-10-30) and USB rows play, light and record as the track's own pages, SHIFT / SHIFT2 + a key is its mute / its selection there, and OCT- / OCT+ glow and shift the keys' octave (on GLOBAL's tempo line OCT is the tempo nudge, as before).

Only the pages whose keys have a job of their own play nothing, send no MIDI note, light no key, pick no lane and record nothing (`keys_none`: the ISR's `ly_lock` is LY_STEP there and `op_drain` drops the presses): PROJECT (a white key picks and runs a slot; OCT its banks) and SONG off its PATTERNS row (the scenes, the parts window). Their keys stay theirs too on SONG's PATTERNS row (the LFO layer's keys), TEMPO (PLAY held: a white key taps the tempo), NAME, the memory list and the Wi-Fi password (they type, `page_owned`), and in a held layer.

ALGORITHM follows the same rule (`algo_has_track`, using the header's classification): it walks on the mixer, SOUND, STEP, SCOPE and the layers EDIT, SCL, STEP and FM6's ENV. It does nothing on PROJECT, SONG (its patterns row and the LFO-held patterns screen included, 2026-10-21; the scenes table moves its cursor along the scenes with it), TEMPO, NAME, the BLE list, a question, the master FX opened by FX, and the layers FX, ARP, GLO, LFO. On GLOBAL and SYSTEM it scrolls the cursor one line a detent. The master FX and the returns' pages reached by walking keep the walk, so that it leaves them (`fx_by_walk`).

## 3. The look

### 3.1 Cards and lists

- **Cards are 2 x 2** on every screen with cards except the mixer's channel and lane rows (which want the height and keep four small cards; its MASTER row takes the big cards). KNOB 1 top left, 2 top right, 3 bottom left, 4 bottom right; label small at the left of the label row, unit right-aligned in it, the value large, its form under it, the hot card white. There is no CARDS setting (settings word bit 23 is reserved).
- **Under the cards**, a screen shows its picture alone on the rest of the panel when the picture is worth it: the envelope (ENV, ENV2), the LFO wave, the arpeggio (ARP, every row), the scale, the gater, the pattern's steps, FM6's algorithm, TEMPO, SCOPE. A row's picture is its family's nearest one (LFO DEST shows the LFO).
- **No picture: four lines** (`FELUCCA_PAGE_LINES`, 1; the builder item was retired 2026-10-21). EDIT, VOICE, a lane's pages, PROJECT, SONG, the master FX, and SOUND pages whose picture only repeats the cards (the FX needles, a lane's name and kit) show the cursor row as four lines in GLOBAL's look, value k on line k, SELECT the next row; the header names the row and its n/N. With the flag at 0: the 2 x 2 cards with the row list (five rows of 19 px) under them. `pl_on`, `pl_draw`, `pic_useful`.
- Lists put a row's name in a column (9 characters from x 4) and its four cells at x 84 + 38 k; a longer text pushes its neighbours right, and only a row that cannot hold every text whole gives up characters, the longest first (`row_layout`).
- The cursor row is the line's colour at full strength with black or white ink chosen by contrast (`ink_on`: no text on a fill is hard to read on the FM-1). GLOBAL / SYSTEM's cursor line is inverted instead: the line's colour as text on black. The BLE devices list keeps its own rows.

### 3.2 Forms

Every value has a form beside its number, chosen from its descriptor's range, never per parameter (`cell_gauge`, `draw_gauge`):

| Value | Form |
|---|---|
| number, min 0 | bar from the left |
| min < 0 < max (PAN, FILT, TRANSPOSE, depths, a drum TUNE) | bar from the centre |
| list of up to 12 | segments, the current one lit |
| longer list | a tick on a line |
| on / off | a pill (GLOBAL / SYSTEM: a square mark at the right) |
| a name, an action | text |

### 3.3 The header

Badge, title with n/N, bar.beat. No tempo (the user, 2026-10-31: "remove the bpm from the title bar. we have it on long press on play button"): it is on the TEMPO page, PLAY held. The badge is the selected track's number and engine in its colour (*2 DIGITAL*, *4 DRUMS*; a picked lane *4 SNARE*; *4 ACCENT*), as coloured text with a 1 px underline, no fill. It shows only on pages whose values belong to the track: SOUND and its families, STEP and a held step's cards, ERASE / KEY / FM6 layers. Every other page's badge is its name in the neutral colour: MIX, MASTER, PROJECT, SONG, TEMPO, SCOPE, GLOBAL, SYSTEM, NAME, a layer's name (FX, REPEAT, MIX, SCENES, PATTERNS). MASTER has no instrument. The title is the cursor row's name alone, never the screen's word, with its continuation number (*Edit 1 2/7*), the n/N grey. bar.beat always stays: a title short of room takes a short form from the names table (`NM_SHORT`: *Pat*, *Scl2*, *Vox2*, *Kit snd*), never a cut. GLOBAL / SYSTEM show a battery icon. A track change flashes the full name (badge, engine, preset) for about 1.5 s on the three synth tracks (`OP_TFLASH_FRAMES`). The rule under the header turns red ~1 s after a drop-out and amber after another underrun.

### 3.4 Names and case (`op_names.c`)

One table names every thing, looked up when drawn; what cells, rows and help lines key on stays the shared name, so the web editor and `tools/param_help.json` are untouched. Three forms: a **title** (sentence case, at most 9 characters, fits whole with its n/N beside the widest badge), a **card label** (capitals, at most 6; an action's object 8), a **list cell** (4 characters, never cut: ANLG DGTL PHSE, LOAD SAVE CLR INS DEL). The mixer's 1x4 cards use narrow forms where a label and its unit cannot share the row (LVL, REV, DLY, CHO): the label gives way, never the unit. One send order everywhere: REV DLY CHO. Preset, kit, lane, voice and project names are drawn as stored. `tests/ui_optimist_names.h` walks every name.

### 3.5 Colour means something

- A track is drawn in its engine's colour (the drum track: its kit's kind, a lane its source's), from `tools/colors.json`; there is no colour per track number. Every colour that can sit under text holds white at 3:1 or better; SUPER is magenta so ANALOG, the drum coral and SUPER stay 15 degrees of hue apart. The palette is fixed (there is no COLOR setting).
- **C_AUTO** (pale yellow, `#ffec80`): a step carrying a lock or a motion event of the sound; **C_NOTE** (cyan, `#4de6ff`): the note a held step's SELECT picked and the note picker's frame. Red only destroys or replaces; amber is changed, pending, gain reduction, a notice; dim is free or unused; grey is a read-out. A muted track is struck through (a 1 px line, 2 in the large face) in its row name, header badge, and its volume card's label and value.
- Mute tiles of the GLO layer are outlined while the track is heard and filled only when muted.

### 3.6 Empties and geometry

- A knob with no parameter is its frame alone (no label, no dash). A parameter with no value says one "-". A slot with nothing says EMPTY, dim. What the build lacks never shows. No page has one card, except the kept SCL 2, TEMPO's REC 2, PROJECT's Memory and the groups of two or three (SENDS, ENV dest, CMP).
- A long name on a 1x4 card with an empty card after it is drawn two cards wide (`card_wide`).
- Nothing else draws in the help band (219..236) in a build with the help line: it is reserved whether the line shows or not, so nothing jumps.

### 4.3 SOUND

The selected track's pages as rows, in `core/params.c` PAGES order, with the page buttons narrowing to a family (LFO shows LFO, LFO PHS, LFO DEST, LFO 2, LFO2 PHS, LFO2 DEST; ENV the envelopes and DEST rows; FX the track's effects; EDIT the engine's rows; SCL, ARP theirs). The whole list is shown when SOUND is entered from the master FX or by a walk.

- **EDIT opens on MAIN**, the four values that matter most: a synth engine's `engine_t.macro` (CUT RES first where there is a filter; FM6 has none and no MAIN), a drum lane's TUNE DECAY CUT LEVEL. One SELECT back is the **SOUND row**: a synth track ENGINE PRESET INIT SAVE AS; the drum track the lane's SRC, ACCENT, INSTR and the KIT. SHIFT2 + PRESETS steps the engine (the next engine's first sound); presets are otherwise picked with PRESETS, so the toasts name the preset and its engine in the engine's colour.
- **Drum track.** The pages are the selected lane's (section 5). With DR itself picked, ENV and LFO do nothing (dark LEDs). A value the lane has of its own is the lane's; a value only the track has stays the track's and is tagged **DR**, amber, top right (the drum bus's inserts "DR ins", the kit send levels "DR sends", Bus send, Slicer, Filter, Gater, Comp, PATTERN, the KIT card). The first SOUND card follows the lane's source: KIT, a PRESET (a lane on an instrument), a SLOT (USR1..3), or dim "-" (ACCENT).
- **FM6**: section 4.12.
- **LFO and LFO 2** (LFO 2 always built; issue #129 B and C, built 2026-10-31, the user: "both lfo are the same"): the two LFOs have the same six values on the same rows, so there is no LFO 3. The family's rows: LFO, **LFO PHS**, LFO DEST, LFO 2, **LFO2 PHS**, LFO2 DEST (titles *LFO*, *Phase*, *LFO to*, *LFO2*, *Phase 2*, *LFO2 to*; the drum track has none of them, its lanes have their own, section 5):

  | Row | KNOB 1 | KNOB 2 | KNOB 3 | KNOB 4 |
  |---|---|---|---|---|
  | LFO / LFO 2 | RATE | WAVE | TRIG NOTE FREE PLAY | POL BI UNI |
  | LFO PHS / LFO2 PHS (two cards) | PHS (degrees) | FADE | | |
  | LFO DEST / LFO2 DEST | DST A | AMT A | DST B | AMT B |

  DEST lists OFF PIT FLT SHP AMP RES PAN LVL ATK DEC E1..E8 (an engine's own names), the other LFO's RATE and AMT, and every value of a synth track's pages (issue 75), the four new ones too (L1 TRG, L1 POL, L2 PHS, L2 FAD).
  - **RATE**, KNOB right = slower then free: 1/64 32T 1/32 ... 1T 1BAR 1BARD 2BAR 3BAR 4BAR **6BAR 8BAR 16BAR**, then free 0.05 Hz .. 40 Hz (a fast turn down stops at 0.05 Hz first, then one note value a detent). The reporter's 1/3 1/6 1/12 1/24 of a bar are 2T 4T 8T 16T. Stored: 0..127 free, -1 4BAR .. -22 1/64 as before, -23 6BAR -24 8BAR -25 16BAR (`core.h LSYNC_LIST`), so no stored value moves; the knob and the gauge walk a place order by length (`params.c lrate_pos lrate_val lrate_rank`; the web editor's knob the same). LFO, LFO 2, the lanes' and the kit's LFOs.
  - **PHS** in degrees (stored 0..127, 1/128 of a cycle, shown v x 360 / 128 rounded, unit *deg*). A detent moves it 45 degrees on the 45 grid (a value off it goes to the next grid value in the turn's direction; 315 is the last, no wrap); **LFO held + the knob, or PRESETS, moves it by one** (2.8 degrees), LEN's fine path (`op_cells.c phs_snap`, `ui.shift`); SHIFT + the knob: 0. LFO's, LFO 2's, the lanes' and the kit's PHS.
  - **TRIG**: NOTE restarts the LFO at PHS on a fresh phrase, its FADE from 0 (LFO as it always did; LFO 2 restarted at 0 before, PHS 0 now); FREE never restarts it (no FADE); **PLAY** (the reporter's T.FREE) takes the phase from the transport while playing: PHS at PLAY, then synced on the bar (beats and units since PLAY: through tempo changes, an external clock, loops of other lengths), free at its rate from PHS; FADE from PLAY. Stopped, PLAY runs on as FREE. `voice.c lfo_play_ph lfo_play_fade lfo1_next` (dual.c draws S&H's value from the same phase).
  - **POL** UNI: one way only, (v + 1) / 2, as LFO 2's always was; LFO's AMP slot from it.
  - **Old projects and presets play as before**: every new value's default is the old behaviour (TRIG NOTE, POL BI, LFO 2's PHS 0 and FADE 0; FADE 0 and FREE skip the multiply, sample for sample: the golden renders unchanged).
  - **Where they live.** LFO's TRIG and POL are part of a sound (`P_L1TRIG P_L1POL`, the sound's last values, `P_SLAST`): a user preset keeps them (UPB4 by count: a preset of before loads them at NOTE BI), a factory preset and INIT set NOTE BI. LFO 2's PHS and FADE (`P_L2PHS P_L2FADE`, the last ids, so `P_COUNT` passes 127: the editor's ids are 2 x 7 bit since protocol 7) are the track's, as LFO 2's others. None of the four is lockable. A project keeps the four in an optional block at the end of its modulation record (`dlfo_rec.c` XREC_TAG 0xD7, after the kit's LFOs; written only when one of them is not at its default, so a project at the defaults is byte for byte one of before; a project without it reads them at their defaults). **An older firmware** refuses a modulation record longer than its own maximum (`dlr_from_rec`), so a project saved with the block loses its whole modulation record there (every LFO slot off); the user, 2026-10-31: "Don't care about that". An older firmware also clamps RATE -23..-25 to 1/64.
- **ENV 1 MOD** has four depth knobs made per engine, the amplitude always ENV 1's. VOICE 2 is ALLOC DETUNE VOICES DROP.
- Pictures: ENV, ENV2 envelopes; LFO and LFO 2 waves (`lfo_shape`, at their PHS, UNI one way); FX slots as needles named with their card's label; the scale on an octave of keys; the pattern's steps; ARP draws the arpeggio over the held notes or a C E G reference, never blank.

### 4.4 The master FX

Reached by FX on the mixer's MASTER row or ALGORITHM left of T1; FX again: the next page. Badge MASTER. The master's own pages only (2026-10-30: the returns' are theirs, section 4.1.1). Pages in the signal's order (`FX_ORDER`, `FX_ALIAS` in `op_screens.c`): **Inserts** (the master bus's slots and amounts), the dynamics (INS DYN 1 THRS RATIO ATK REL, INS DYN 2 GAIN CEIL GR, while a slot holds DYN), JUNO / EQ3 settings while a slot holds them, **Duck**, **Macro** (COLOR MOTN SPACE ENRGY, MACROS builds). Page names are at most 9 characters. TUNE is on GLOBAL's Tempo list. The mixer's MASTER row follows the same order.

### 4.5 SONG

Entered by SAVE held on PROJECT, SEQ held off STEP or SHIFT2 + SEQ (section 1.3). Rows: **SCENE A..P** (T1 T2 T3 DR: the pattern each track plays in it, *KEEP*, *-*; knobs edit the references while stopped, written once they rest; YES launches at the next bar, stopped it loads; REC stores the loop into it; SHIFT + REC clears it; the playing scene green, a queued one amber, *\** a changed one); **PATTERNS** (each track's playing pattern, a turn cues the next; the panel is the 4 x 16 session grid with the preview of a pattern under it, no cards; the keys are the LFO layer's); **MODE** (LOOP / SONG, SONG REC, the MEM gauge, SAVE writes the chain) before the parts; **PART 1..64** (SCENE BARS INSERT DELETE, edited stopped, the part playing white). The chain is saved when SONG is left, stopped. Without PATTERNS a scene says STORED / EMPTY.

### 4.6 PROJECT

Rows: PROJECT, SNAPSHOT, USER, TOOLS (CLEAR SEQ, INIT SOUND, MISSING, NEW), MEMORY (USED, FREE). In SD card mode the card's lists come first (PROJECT on the card, PRESETS, KITS, SAMPLES: section 4.14). A storage row is four cards (`op_prjflow.c`):

| Card | |
|---|---|
| 1 BANK | the bank of 16 slots the keys are; only on a store of more than 16 (USER: 32) |
| 2 ACTION | LOAD (default), SAVE, DELETE. PROJECT has no DELETE (NEW is the blank project). Red when it would destroy or replace |
| 3 ITEM | the slot; walks all of them across the banks |
| 4 | PROJECT: NEW; USER: INIT; SNAPSHOT: empty |

The 16 white keys are the slots of the bank: key n selects item n and runs the action through the confirm. YES runs it on ITEM. A free slot to DELETE (or, on SNAPSHOT and USER, to LOAD): a toast, no question. LOAD of a free PROJECT slot offers a new project there (2026-11-01: "when user try to load from empty project slot, offer to create/init project"): *NEW PROJECT 3?*; YES makes the clean project NEW makes (default sounds, empty patterns, default BPM) the open one and stores it in that slot, toast *NEW PROJECT 3*; HOME cancels and changes nothing. With edits not stored, the usual discard question comes first (*SAVE PROJECT 2?*, HOME = not saved), and the red *NEW PROJECT 3?* follows. The action returns to LOAD after each action, when the row changes and when the screen is left, so a stray key never saves. OCT- / OCT+ tapped pick the previous / next bank. SHIFT2 + ITEM on USER marks a favorite. Under the cards: the bank as a strip (used filled, free outlined), the sentence the key would run, the item's name and what is stored (a project's name from the section log, a snapshot's status and size, a user preset's engine). Projects and user presets are named on NAME; project names are record 21 of the section log with PATTERNS, else 23 (16 x 12 bytes, `sections.c SEC_ID_NAMES`); builds with four RAM project slots save unnamed. Kits keep numbers.

### 4.7 GLOBAL and SYSTEM

Two settings lists, one setting a line, pages of four lines, no cards (`op_global.c`, `op_gldraw.c`). GLO tapped switches between them; each keeps its cursor line. KNOB k edits line k of the page and makes it the cursor; SELECT moves a page; ALGORITHM moves the cursor a line, across pages; PRESETS does nothing; SHIFT + a knob resets to the default (or the factory value; BLE is never reset); SAVE is YES on the cursor line (an action, a toggle). OCT-/OCT+ held on a page with Tempo's lines nudge the clock; elsewhere the octave.

A page is one section; sections are never combined to fill a page except one joined pair when together they fit four lines (*General* with USB SERIAL). Only a section of more than four lines is split between rows. Pages are built from the lines the build has (`gl_build`), so no page number is fixed. A line: name left, value right in the large face where it fits, its form under it; read-outs grey, actions their verb; the line's colour is the knob's with KNOB COLORS. The help line shows the cursor line always.

| Screen | Sections |
|---|---|
| GLOBAL | Tempo (BPM NUDGE SWING TUNE), Rec (MODE LENGTH START CLICK, then QUANT, PUNCH: with the arena's extras only), Filter (FILT RESO: every track's FILTER resonance, 0 .. 10, saved with the project; builds with the track FILTER, moved here from SYSTEM > General 2026-10-29), MIDI (CLK IN: AUTO, LINK (Link builds), TRS, USB, BLE (BLE builds), INT, in AUTO's own priority order, AUTO first and INT last; CLK OUT: OFF, USB, BLE, BOTH (without BLE: OFF, USB); LINK (Link builds): OFF, ON = tempo and beat, ON+S/S = also start / stop, the default; MIDI OUT: OFF, KEYS, SEQ, BOTH; CLK OFS, BT OFS, LINK OFS (Link builds): the steps that much earlier while following a clock, on the FM-1's output / on Bluetooth audio / on Link, the PLAY-held NUDGE card edits the followed clock's value), Channels (T1 T2 T3 DR) |

A join picks the strongest access point of the name, not the row.
- **USB** (2026-10-28; `ui/optimist/op_project.c` SI_UHMODE / SI_UHDEV, only in the release with the builder item `USB_HOST`: fm1-base's USB host, the trial's `ui/opt_usbh.h`): MODE and DEVICE. - CALIBRATE > PANEL asks first and cancels after 30 s of no input. MIDI IN is not a setting (notes come through the track channels). The second core is always on; `dual_mode` stays AUTO and the guard's reason shows on INFO.
- Leaving SYSTEM or GLOBAL saves a changed setting, once stopped.

### 4.10 SCOPE

HOME tapped on the mixer (again: back; section 4.1). One row, one page of cards: the source's values (a track LEVEL PAN FX DRIVE; MASTER FILT THRS RATIO GR; a return its mixer row's LEVEL FX). The source is ALGORITHM's: the selected track, a lane counts as DR, MASTER the master output, a return (RET A B C, `ui.sret`; the user, 2026-10-31: *"if i am on, say, ret C on mixer, i click home ... it should go to scope ret C"*) its output after its POST and level (`fx.c` `SC_RET`, `scope_src` 5..7 the line; what SYSTEM > USB AUDIO's RET taps take, then its POST and level); it stays on SCOPE. HOME from the mixer's row opens SCOPE on that row's source. The panel is the oscilloscope: trigger-stable (the latest rising zero crossing after a swing below peak / 8 that leaves a whole screen), 236 points two frames apart (10.7 ms), scaled to the peak, 30 frames a second, in the source's colour. ### 4.11 NAME

## 5. The drum track

- **10 lanes plus ACCENT**, each playing an instrument the user picks (SOUND's LANE row, KNOB 3 INSTR; 18 instruments, KICK .. CLAVE) and named after it everywhere. A lane set to an X0X voice takes its instrument. Core: `DRUM_LANES` 10, `DRUM_ACC`, `DRUM_UILANES` (`core/core.h`); `drums.c INST_*`, `lane_of_key`.
- **Keys.** The 16 white keys are steps of the selected lane on every page; the 11 black keys select and play lanes (F#3..D#5 lanes 1-10, F#5 ACCENT). A lane key picks its lane on every page and plays it when stopped or recording, silent while playing (SHIFT2 + the key auditions it). A drum key played selects its lane on the pages where keys play, but not within 300 ms of a knob turn. MIDI in: a GM note plays the lane on that note, else on its instrument, else of its family.
- **ACCENT** is a silent lane: its steps raise every hit of the step by the amount `P_DACC` (default 27). It has no sound pages and no step key (it is not a step). Its sequencer mute is SHIFT + its key or SHIFT + its card's knob on the mixer.
- **A lane's values are events.** On the drum track the parameter `AUTO_LANE0 + (lane << 3 | value)` is the lane's TUNE DECAY SNAP CLICK BEND CUT DRIVE LEVEL offset, a lock on a step or motion; applied at the hit through an overlay (`drums/lane_play.c dla`), never written to the lane's own values. REC held + a lane knob records them while playing.
- **Each lane has its own LFO, LFO 2 and ENV2** (per hit, two slots each: a DEST among the lane's values and an AMT; ENV2 ATK DEC SUS RTRG): pages LFO, LFO DEST, LFO2, LFO2 DEST, ENV2, ENV2 DEST, only with a lane picked. They are kept in their own record (`storage/dlfo_rec.c`, log ids 122..138), not as automation events, so they are not recordable.
- **Sends are multipliers**: the drum track's REV DLY CHO scale each lane's send of that bus; the drum bus sends nothing of its own.
- **Preview.** A lane picked previews once when the transport is stopped, silent while playing (`lane_pick_from`, `audition_lane`).
- **PRESETS by source**: DR or a lane on KIT: the kit; a lane on an instrument: that lane's sound only; SHIFT + PRESETS (SHIFT2 before 2026-10-31): the first sound of the next kind (your samples, a sampled kit, a synthesised kit, X0X); SHIFT2 + PRESETS does nothing on the drum track (no filter on kits).

## 6. Recording

- REC: playing, records the selected track at once, again stops. Stopped, arms: the first note starts the loop, or the free take on an empty project, or the count-in (REC MODES). A take ends at a pattern switch. Overdub and latency compensation as in the core.
- **REC tapped, then pressed again at once and held** (within 0.4 s, held 0.5 s; SD card builds with SD_REC): a take of the master output on the SD card starts, the same again stops it (*CARD REC REC-0001.WAV*, *CARD STOP*); the tap's arm is put back, that press never starts the clear ring, a second press let go sooner is a plain REC press. REC flashes while the card records. A take that fills its file says *CARD REC FULL*, a card that fails *CARD REC FAILED*.
- **REC held** clears. A ring fills after 0.7 s (the press is undone) and 1.3 s later the selected track is cleared (undoable, toast *T2 cleared*); let go before: nothing. With a lane picked only that lane (*Clear SNARE*). **REC held + a knob** clears that parameter's motion and p-locks over the whole track (a lane value: the lane's); the turn stops the ring so the track is never cleared this way. **SHIFT + REC held** clears the track's (the lane's) motion, p-locks, nudges, fills and chance; notes, levels and recorded lengths stay. SHIFT + REC on a SONG scene row clears the scene (asked).
- **PUNCH** (TEMPO's REC 2 / GLOBAL's Rec, per project, saved in the G_INFO slot, bit 1 = ON; only in a build with the
  arena's extras, `FELUCCA_PUNCH_SW`, the SD card mode): the punch-in FX's ring of the mix is held in the arena while it
  is ON (docs/SD-MODE-DESIGN.md 6b). OFF (a new project's, an older project's): FX + a white key plays nothing, *PUNCH
  OFF*; no room for the ring: *MEM FULL PUNCH*, the punch bypassed until there is room. Other builds: the ring is
  static, the punch always there, no switch.
- **REC QUANTIZE** (TEMPO / GLOBAL, per project, saved in the G_INFO slot, bit 0 = OFF): ON (default) snaps a recorded note's start and length to whole steps. OFF keeps the start as the step's nudge (own steps only, with MICRO) and the length as TIE steps plus a GATE lock on the last step (`rec_len_end`): a NOTE plays GATE / 128 of a step. Within 4 of the track's GATE: no lock.
- **Overlapping notes** (POLY): a note keeps sounding while others are played over it. The new step becomes a chord of the new note and the held ones with the step flag `SF_CARRY` (`step_t.flags` bit 7; chance uses bits 2..6): carried notes already sounding go on, not struck again. MONO / LEGATO / UNISON keep one note a step.
- **Each note's own end** (POLY, REC QUANTIZE OFF): a note up while others are down ends at its own time. The byte `step_t.ngate` (ends at ngate / 128 of the step) lives in RAM; stored as step-only events `AUTO_NGATE0 + k` (0x78..0x7B, `seq/ngate.h`). A chord's keys up within 1/8 of a step share an end. A note's length is measured through TIEs and carry steps (`note_span`, shared with the web editor's `noteSpan`).
- Undo, redo and the song: sections 2.6 and 4.5. SONG REC (SEQ + REC) records the scenes you launch and their bars.

## 7. The automation store

One list of events per pattern (a track's working pattern; a pattern record carries its own), at most **128**, each 3 bytes (`seq/auto.h`, `auto.c`, `auto_base.c`):

```
byte 0  place: bits 0..5 the step, bit 6 STEP-ONLY (0 = hold: motion; 1 = this step only: a lock), bit 7 reserved
byte 1  the parameter: a stored id, or a pseudo-parameter
byte 2  the value, a signed byte (every lockable or recordable value fits: tests/auto_int8_check.c)
```

| Gesture | Writes |
|---|---|
| a step held + a knob | a step-only event (a lock: the parameter goes back at the next step without one) |
| REC + a knob while playing | a hold event (motion: until the next event of that parameter or the pattern restart; STOP puts the patch back) |

Ids: stored track values (`mot_sid`, build-independent); the ACCENT amount `AUTO_ACC` 0x77; note ends `AUTO_NGATE0` 0x78..0x7B; drum lane values `AUTO_LANE0` 0x7C + (lane << 3 | value); insert-slot values `AUTO_SLOTP`; mutes `AUTO_MUTE0` 0x6C (+ lane 0..9, `AUTO_SMUTE` a synth step); pseudo-parameters `AUTO_COND` 0xFC (1..9: 1:2 .. 4:4), `AUTO_NUDGE` 0xFD (-32..31, 1/64 step), `AUTO_FILL` 0xFE (1 FILL ONLY, 2 NO FILL), `AUTO_CHANCE` 0xFF (0..99 %). Chance, nudge, fill, condition are step-only events on drums and synths alike; the drum chance is the step's (every lane together).

`auto_step(t, idx)` applies a step's events in list order in one scan: hold events set the value and leave it; step-only events save the base and let go at the next step without one. On the same parameter the step's event wins on its step; the base a lock returns to is what a hold left. A fill-skipped step skips its step-only events, not its hold events. Every lockable value is recordable and the other way round (`auto_param`); excluded: voice allocation, MUTE, FX OFF, LEN DIV SWING, the LFO DEST slots, values with no stored id. A micro-timing index of nudges (`auto_nudge`) is rebuilt when the list changes, never per sample. At most 24 locks apply at once.

Storage: with the section log a store is written in the new forms (the extras record's `AUTO_ENC_TAG` form, a pattern record V2 for a track with automation); the old MOTN / stepx forms are only read. Four-slot builds (no log) still write the MOTN record (64 hold events). Undo copies the track's list. SLOOP 2.4 import turns its nudges, 24 locks and fills into events (a lock clamped to int8 says so); its export rebuilds nudges, fills and the first 24 step-only events and reports the rest lost (*MOTION NOT IN 2.4*, drum lane values, drum LFO, conditions). The web editor reads and writes the list with AUTO_GET / AUTO_SET (web/EDITOR_PROTOCOL.md).

## 8. Sequencer features

- **Sequencer mutes** (one mute, the sequencer's): a muted track or lane triggers no new notes (internal sound and MIDI out), its steps' locks do not apply, sounding tails finish; its recorded motion keeps running; notes played live still sound. Saved with the project in the FX record (TLV 0x43: the tracks' bits, the lanes' mask, `seq/seq_mute.c`). A sound mute an older project left shows as muted and the toggle clears it.
- **Conditions** 1:2 2:2 1:3 2:3 3:3 1:4 .. 4:4: the step plays on loop a of every b of its own track (counts from PLAY, a song section, a launched pattern). Order on one step: condition, FILL, chance; a failed one is a REST. Edited on the held step's EXTRA page, 4th card COND.
- **TOOLS**: REVERSE mirrors the steps inside LEN (a note moves whole: ties and carry steps with it); RANDOM keeps a synth track's rhythm and gets new scale notes (SCL CHR: the minor pentatonic of ROOT), a drum beat on DR, a lane drawn the same way; COOK changes 15..25 % of notes (drums 10..20 % of hits; never a lane's last nor the kick on step 1); LENGTH x2 copies the steps after themselves (64 at most; refused when the events would pass 128), x1/2 halves LEN. Events move with their steps. The EDIT layer's SHIFT and LENGTH move and copy events too.
- **GEN** (`seq/gen.c`): a note generator is a layer the sequencer plays over the pattern, never written into it. One slot per synth track and per drum step lane; several on at once. TYPE EUCLID (HITS STEPS ROT), RANDOM (DENSITY % SEED ACCENT %; its own hash, so chance rolls are undisturbed), PULSE (EVERY OFFSET RATCHET), GRIDS (X Y DENS, builder item `GEN_GRIDS`). **GEN OUT**: GEN on / off, MODE (REPLACE: the hits are the steps; ADD: pattern plus hits; MASK: the pattern only where it hits), WRITE (asks): bakes exactly what plays into steps 1..LEN and turns the slot off; one undo level brings back the pattern and the ON. A synth hit plays the pattern's NOTE, else a TIE's, else ROOT near C4. The grid draws a generated hit outlined and a silenced pattern hit as a dim stub. Saved with the project and each scene (a TLV of the FX record, `GEN_TLV` in `seq/gen.c`).

## 9. Track insert slots and effects pages

Each track (T1 T2 T3, DR) has **two insert slots** S1 and S2, run after the SLICER; a slot holds DIST, FILTER, COMP, GATER, EQ3 or another insert type, or nothing. A type once per track: turning a TYPE skips the type the other slot holds and the ones that would not be heard. The amount belongs to the type, so a lock or motion on an insert's card follows the type. A new track: S1 DIST, S2 FILTER at 0. The master has four slots (`INSERTS` shows two slots and amounts; DYN, JUNO, EQ3 are insert types) and the sends; the USB input has the same two. A drum sound's own DST and CMP are always heard. Code: `fx/fx_slots.c`, `ins_map` for old projects.

SOUND > FX pages (`op_screens.c`): **Inserts** (S1 TYPE, amount, S2 TYPE, amount; a TYPE card lists ---- (empty) then the types built, A to Z: `fx_slots.c` FXT_ALPHA, fixed at compile time; no lock or reset on a TYPE card), **Comp** (RATIO ATK REL) only while a slot holds COMP, **Gater** (DEPTH PAT RATE SHAPE; 16 patterns) only while a slot holds it, **Sends** (card k is the send of return A, B or C; REV DLY CHO by default), **Bus sends** (drum track). FX + KNOB 4 is the track FILTER amount (*FILT: NO SLOT* when no slot holds it).

ECHO (and since 2026-10-29 the CHO DLY REV inserts; CHRS until then) are insert types of which the build holds 0..4 instances (`fx/insfx/fxi.c`). The TYPE cell is the picker and says what it holds: *CHRS 2/4* (free of available), *FULL* dim (bypassed on this track), *IN USE* for a frame, *WAIT* for one pass. Types with 0 instances built are not listed. `fxi_cap fxi_free fxi_state fxi_can`.

## 10. Effective values: one number, two bars

On every card the big number and its bar are the value as entered. While the actual value differs from it, a second bar shows the actual value now (white, amber on the hot card, 2 px, no trough); a bar whose value returns stays 400 ms so an LFO crossing it does not blink. The UI recomputes from RAM the audio side already keeps (`op_effval.c effv_cell`); nothing is published and nothing runs in the ISR. A moving bar redraws only its 2 px strip, at most every 33 ms.

| Card | The actual value |
|---|---|
| a drum lane's value | what a hit plays now: the patch, the lane's motion and locks, its LFOs and ENV2 (`dl_play_ofs`, the hit's own formula) |
| a synth cutoff or shape card | the card plus the part's modulation now: LFOs, the newest voice's envelope, the accent, the macros (`mac_effective`) |
| an LFO / ENV DEST card, ENV 1 MOD | the destination's actual value on its scale, while the amount is not 0 |
| PIT, AMP, RES, PAN, LVL, ATK, DEC, E1..E8, CHO DLY REV, INS1 INS2 | the value as the render has it, moved by every slot on it in turn (`lo_move`, as `voice.c lfo_over_in`) |

Not on a held step's cards or the layers' cards. Not counted: an ANALOG 2 part's own ENV2 and keytrack, CZ's amplitude curve.
