# FM-1 scene survey, early October 2026: what to integrate, what to borrow

Read-only survey, written 2026-10-05. This note is uncommitted. None of our repos were changed.

**How the survey was done:**
- GitHub: repo and code search, and the fork network of Felucca, SLOOP, Lunar Modulator, FM-1-RE, aroum and the emulator. Each fork was compared with its parent through the compare API.
- Issues and discussions of the main firmware repos.
- Web: Synth Anatomy, Piano & Synth, Sonicstate, groove-os.com, baudgirl.com.
- Reference clones, read-only, in `~/GitHub/refs/<name>`: Felucca, fm1-x0x, flowstate-fm1, chance-felucca, renebohne-sloop, renebohne-felucca, sloop-upstream, melodee-latest, jangada-upstream, lunar-modulator, lunar-modulator-looper, fm1-nes, Virtual-FM-1, FM-1-RE, fm1-custom-fw, fm1-emulator-upstream, mvave-fm1-open-firmware, fm1-workbench-public, fm1-firmware-patcher, fm1-dx7-patch-importer, fm1-polyseq.
- Scratch builds, from `git archive` copies in the session scratchpad with our Docker toolchain:
  - Felucca 1.0.1 builds to **477,004 B**, the same size as its release `app.bin`.
  - X0X 0.9 builds to **580,068 B**.
- Both packages were also booted in our emulator (`fm1-emulator-boot` at `7a220f4`).

## 0. The short version

- **Felucca is back, and at 1.0.1** (`hugelton/Felucca`, re-created 2026-10-02; v1.0 2026-10-05, v1.0.1 2026-10-06).
  - The old handoff note said "that repo is gone". That is no longer true. Melodee is now a GitHub fork of it.
  - It has 13 engines: FM6 (an Apache-2.0 port of msfa), PHYS (DaisySP/Rings, MIT), NOISE, DRUM, SLICE and others.
  - Other new features: a piano roll, per-step chance, motion recording, spring reverb, a harmonizer, a modulation matrix, USB audio, TRS MIDI, web backup/restore and return to V15.
  - It all fits in **477 KB**.
  - Its build trick `size_fns.py` (LLVM `minsize` on UI code only) saves **8,068 B** [M]. That is more than twice our 3,812 B overflow.
- **X0X** (`charlesvestal/fm1-x0x`, GPL-3.0-only, Felucca-derived, 78 commits in 3 days) is the best-documented hardware bring-up so far.
  - **The CPU runs at 360 MHz**, read from the PLL registers on a real FM-1 [R]. Our old handoff note said ≤320.
  - Its other hardware lessons: encoder and LCD fixes, float divide-by-zero traps, a USB-audio clock that drifts against the host, and 512-frame audio halves.
- **SLOOP upstream** is still at 2.2 (`f2b44c2`), which we already contain [V].
  - Its forks: **Flowstate** (78 commits of "Musical Worlds", guardrails and an SDL simulator) and renebohne's played-notes LEDs and a visual FM UI.
- **The emulator upstream** is unchanged at `81b9ed9`.
  - Issue #1 (cliph, 2026-10-05) lists three gaps for Felucca 1.0. We already decode the two instruction forms; **we do not model USB EP4** [M]: Felucca 1.0.1 stops at `USB endpoint index exceeds modeled controller`.
  - X0X stops on the corex2 perf counter at `0x01EEE218` [M].
- **New hardware facts** (§3) change our CPU budget, emulator calibration, LCD speed and safety rules.

## 2. Per project

### Felucca: `hugelton/Felucca` (Leo Kuroshita / Hügelton)

| | |
|---|---|
| Licence | **GPL-3.0-only**, plus MIT / Apache-2.0 ports (`LICENSES/`) [V] |
| Last activity | v1.0.1 on 2026-10-06 (`20c275e`) |
| Activity | 201 stars, 20 forks |
| Tags | v0.8-beta, v0.9-beta, v1.0, v1.0.1 |

- **What is new since 0.9 (our base)**, in one 37 k-line commit `727f272`:
  - **Engines:** 13 engines. FM6 is an integer port of Dexed's msfa in `fm6_core.c` (Apache-2.0). It replaces DIGITAL, and old DIGITAL sounds convert. PHYS covers MODAL, STRNG, MEMB and sympathetic strings. NOISE covers colours, crackle, LFSR and metal. SLICE now has manual slices. DRUM is an 8-lane GM kit.
  - **Sequencer:** piano roll, drum grid, songs A–D, motion recording, per-step chance, divisions up to 4 bars, ARP REPEAT, chord keys with voicings.
  - **FX:** an FX hold layer (repeat, reverse, filter, tape stop, freeze, harmonizer), spring reverb, and a 4-slot modulation matrix per track with MIDI CC sources.
  - **UI and system:** on-device naming, 8 palettes, an Inter Tight anti-aliased font, Fukiai icons, USB audio input, TRS MIDI in with bend/sustain/clock, web backup/restore, sample recording and trim, return to V15.
  - **Tests:** about 30 new host tests.
- **v1.0.1:**
  - dim idle LEDs ("a short pulse riding on the 595 shift");
  - LEDS INV;
  - key LEDs follow the sequencer (#38);
  - QNT SEQ (#37).
- **Size:** image 477,004 B, RAM 88,884 B, pool 329,952 B [M].
  - Samples are 194,056 B ADPCM (5 sets). Ours are 315,854 B. That is where its headroom comes from.
  - The `minsize` pass is worth 8,068 B [M: `FELUCCA_SIZE=0` builds 485,072 B].
- **Relevance:** **integrate selectively** (§1 #1, #2/#3, #9, #10, #11).
  - It is the same licence and the same HAL family, so ports are cheap. But its project format, UI and engine list have diverged from SLOOP's.
  - SLOOP users already ask "are you going to implement the new things of Felucca 1.0?" (SLOOP #14 comment).
- **Community wishes**, from issues #39–#59 opened 2026-10-05:
  - parameter locks, macros/scenes, generative/mutation tools;
  - knob acceleration, a BPM lock, HOME as shift, temporary modifiers;
  - ratchets for notes, dry/wet FX with a phaser, FM6 per-operator editing;
  - Bluetooth MIDI (#17, still open).
- **Discussions:**
  - #43 asks for the X0X 606/808;
  - #4 asks for TRS MIDI (now in 1.0);
  - #36 reports a port named "Kartun Oscuro" and a lost connection after install (unexplained).

### X0X: `charlesvestal/fm1-x0x` (Charles Vestal)

| | |
|---|---|
| Licence | **GPL-3.0-only** [V] |
| Last activity | 0.9-beta on 2026-10-05 (`80b7d40`) |
| Origin | Fork of Felucca 0.x |
| Activity | 78 commits from 2026-10-03 to 10-05, 12 stars |
| Developed with | Claude Code, per its commit trailers |

- **What it is:** a ReBirth-style instrument:
  - 909 (from 9W9 / ER-99) and 808 (from 8W8);
  - two 303s (Open303 with Devilfish) with TB-3PO generators;
  - a break player (BB Gen, used by permission);
  - 16 patterns, polymeter, song mode, motion;
  - a master compressor with kick-keyed PUMP, a filter and a limiter;
  - USB audio input with a resampler, USB MIDI clock in/out;
  - help cards, undo by difference, autosave of changes only, a PERF test and an on-device load meter.
- **Size:** image 580,068 B, RAM 65,068 B, pool 316,272 B [M].
  - Per module [S]: 303 11,550 B, TB-3PO 1,427, 808 30,504, 909 256,386 (it holds hat and cymbal samples), FX 20,457, master 5,963, motion 1,290.
- **What is unique and valuable to us:** hardware measurements (§3) and the fixes they led to:
  - the encoder filter;
  - TIMER5 priority above ALNK0;
  - LCD SPI speed and dirty rectangles (the panel's TE output is not wired);
  - the float div0 trap;
  - the I2S clock against USB;
  - 512-frame halves;
  - the second-core start sequence from the SDK (it matches our `docs/DUAL-CORE.md`);
  - the `fm1_rescue.py` UBOOT restore.
- **Relevance:** **integrate** fixes and tools (§1 #2–#8, #14, #15, #17). **Inspire** on engines; an ACID engine is possible (§1 #12).
- **Licence caveats:**
  - `dsp/breaks*` is used **by permission** of BB Gen's author, and that repo has no licence. Do not copy it.
  - Open303 parts are MIT.
- **Our emulator:** it stops at `0x01EEE218` (perf counter MMIO), which is not modelled [M].
- **Open issue #1:** "digix0x as a better 303".

### Reverse engineering and tools

- **FM-1-transporter** (`kurogedelic`, MIT, 2026-10-01):
  - an RP2040 USB_KEY dongle and UBOOT client;
  - documents UBOOT 4C4A:8057, chip key `0x980F`, the stock V15 soft key `F0 22 24 35 7D F7`, and that raw flash = the `.fwsc` flash entry.

  - Relevance: **integrate** the protocol via the rescue tool.
- **AL-255/FM-1-RE** (WTFPL, 2026-09-08):

## 4. Top 10 recommendations

1. **Port Felucca 1.0's `minsize` UI build** (`size_fns.py` + `build.py` IR step).
   - It is −8 KB on Felucca [M] and very likely clears our 3.8 KB flash overflow without trimming samples.
   - Measure it on `feat/integration` first. Effort S.
2. **Fix the encoders:**
   - X0X's decoder (no two-scan filter, flick continuation);
   - Melodee's first-detent fix;
   - speed acceleration for continuous parameters.
   - Port the host encoder tests too.
   - These are the most-reported hardware bug across SLOOP and Felucca. Effort S.
3. **Correct our CPU assumptions:**
   - Write "360 MHz measured by X0X [R]; stock sets 240 [R]" into MEMORY-BUDGET.
   - Add a TIMER4-timed busy-loop readout to our hardware probe build so that **our** clock is measured on the first hardware session.
   - Calibrate the emulator's cycles-per-instruction against it. Effort S.
4. **Emulator: model USB EP4, the corex2 perf counters and the float div0 trap.**

   - Coordinate with cliph's patch (emulator issue #1) before the upstream PRs. Effort S–M.
5. **Raise the LCD SPI to 30 MHz** (BAUD 1), then consider dirty-rectangle sends.
   - It frees main-loop time and removes tearing.
   - Hardware test needed; X0X runs 60 MHz [R]. Effort S.
6. **Audit for divide-by-zero**: integer divisors in the UI, clock, tempo and the adaptive tracker. Our HAL traps div0 and a trap means a crash on hardware. Optionally clear the trap as X0X did. Effort S.
7. **USB audio clocking:**
   - Test `feat/usb-audio` under live monitoring against a drifting I2S (~44.15 kHz).
   - If packet-size feedback drops out as X0X reports, adopt X0X's resampler (`80b7d40` + `uac_test.c`). Effort M.
8. **Safety kit for the hardware phase:**
   - adopt X0X's `fm1_rescue.py` (macOS, UBOOT, hash-checked V15, changed sectors only);
   - adopt Felucca 1.0's web **full backup/restore** and **return to V15**;

9. **Cheap Felucca 1.0 / fork features as builder switches:**
   - per-step chance;

   - QNT SEQ;
   - spring reverb;

### 5.2 What changed

**What a World is.** One JSON file (`format: "flowstate-world/1"`) that describes a complete playable piece for SLOOP's four tracks [V `docs/worlds.md`]:
- metadata: name, category, blurb, tempo range, key and scale, swing;
- four tracks: role, engine, factory preset by name, parameter values by label, drum kit;
- patterns in a text notation: chord tokens `c1`..`c9`, degrees, accents, slides and ties, drum lanes as `x.s.g` strings;
- progressions in Roman numerals;
- scenes A–D: progression, ENERGY table, transition, fill, parameter and FX overrides;
- up to 8 variations: preset swaps, pattern swaps, parameters, an ENERGY bias, macro defaults;
- four macros (COLOR, MOTION, SPACE, ENERGY): up to 40 mappings with curves and smoothing, and up to 8 cross-macro rules;
- ENERGY bands that add layers, drum lanes, density, fills and ratchets as one knob turns;
- Smart Keys: white keys play the melody scale, black keys the current chord's tones;
- a guard block: note ranges, polyphony, parameter ranges, arrangement timing, a CPU cap.

**Storage** [V `docs/design/fwd1-format.md`]:
- `tools/worldc.py` compiles a World to an **FWD1 blob**: little-endian, byte-aligned, a 24-byte header with magic, version, flags, length, an FNV-1a id and a CRC-32, then up to 16 typed sections. Factory blobs are capped at 3,072 B, user blobs at 3,840 B.
- The firmware validates each blob byte by byte (`wb_check`) and never casts it to a struct.
- Factory Worlds are compiled into the app image by `tools/gen_worlds.py` (`build/gen/felucca_worlds.h`). A World that fails `worldc check` fails the build.
- User Worlds ("MY WORLDS", 10 slots) are whole blobs with a USER flag plus an OVERRIDES section of `{scope, id, value}` records. They live in flash `0xE5000`–`0xFBFFF` (`docs/hardware-calibration.md` §3.2).

**The factory library** (Phase 18, `docs/worlds.md` §19, `docs/progress.md` 1150–1313) [R, figures from their logs]:

### 7.4 Top 5

1. **Brightness freeze.** *(Done 2026-10-07, optimist 04be2e6 + cccc218: BRIGHT=0 in user.config and mots.config; the screen boots at full, the saved level is ignored, nothing below 4/16; marked EXPERIMENTAL with a builder warning.)* Remove `BRIGHT=1` from `config/user.config:27` until a hardware test clears it. Mark `FELUCCA_BRIGHT` in `backports.json` as "froze an FM-1 at level 1 (X0X issue #2, cause unknown)". If it stays, start at full brightness on every boot (ignore the saved level), so a dim setting can never stick. Safe mode will probably not save a unit that hangs at the saved level, because a power-on clears the boot guard (`main.c:335`) [I].
2. *(Done 2026-10-07, optimist 04be2e6: the trap is explicitly cleared in fm1_irq.h; the emulator reads EMU_CON = 8.)* **Turn off the divide-by-zero trap** (`fm1_irq.h:72`), as Felucca 1.0.3.1 and X0X did, or prove the ~38 guarded divides in the disassembly. The compiler can run the divide before its guard [R]; a trap before the app is up loops into UBOOT [R: Felucca #61].
3. **USB rescue: discard MIDI channel/realtime events in recovery** (Jangada `0835cc4`). Check on the emulator first that a clock stream during rescue blocks the installer's SysEx in our tree.
4. **IRQ stack high-water mark** on the perf page. Cheap evidence on a 7,936 B system stack that every interrupt shares.
5. **Small UX fixes in one batch:** calibration cancel by any key, the PLAY-frame knob gap, cursor-step notes on the keys; then **ping-pong delay** as a builder option.

### 7.5 Caveats

- Nothing was built or measured; all flash / RAM figures are estimates from diffs or reported by the projects.
- The brightness freeze has one hardware report and no root cause [R]. Our port-A access looks race-free (the key scan and the backlight both write from TIMER5 only; elsewhere only the init write, `fm1_lcd_hw.h:37`) [V by reading], so the risk is unexplained, not ruled out.
- The div0 hoisting is Felucca's report [R]; we did not inspect our own disassembly.
- The USB rescue lockup is a reading of our code against Jangada's fix [V by reading]; it was not reproduced.
- The FloydFM comparison covered ratios, presets, the brightness code and the algorithm names; it was not a line-by-line diff of the whole VST.
- The Casio data's legal status is not decided here; only the facts of its origin are recorded.
- april-os was one day old when read; it may change quickly.
