# Integer divides by a variable in firmware/src and firmware/hal, and why each divisor cannot be 0.
# The HAL keeps the CPU's divide-by-zero exception OFF (fm1_irq.h clears EMU_CON bit 2, 2026-10-07,
# after Felucca 852bc72 #61 / #111): the JieLi clang can run a divide before the test that guards
# it, so the "guarded" reasons below hold in the source but not necessarily in the binary, and an
# armed trap turned that into a boot loop on Felucca (X0X ea3c665 met the trap on hardware too).
# With the trap off a zero divisor gives a wrong value, still a bug, so the list stays.
# Checked by tools/div_audit.py (tests/run_tests.sh): a new divide by a variable fails the tests
# until it is listed here with its reason. Key: file:function:divisor (as the scanner prints it).
# Not scanned: firmware/src/acid and firmware/src/x0x (the X0X ports, the only float code; the scan is not recursive);
# their shared maths src/dsp_float.h is scanned: its three float divides are listed below.
# Audited 2026-10-05 on feat/backports-fixes; one guard added (eng_slice.c slc_fill).
#
# Invariants used below:
#   BPM    song.g[G_BPM] is 40..240: every writer clamps (UI knobs, tap tempo, clock_sync, project
#          load proj_apply, editor SysEx ed_param, free take ft_close via ft_fit's 40..240 window,
#          main.c / ui_input.c defaults; bench.c 120).
#   TLEN   trk_len(t) is >= 1 (returns 1 for P_SLEN <= 0); local "len" copies of it likewise.
#   TABLE  a const table whose entries are all non-zero (listed per site).
#   PARAM  a parameter clamped to its descriptor range by every writer (UI, editor, project load).
